# Q-ENGINE: Quantum PCA for Intelligent Engine Health Monitoring

MATLAB app that loads NASA C-MAPSS turbofan data, runs classical PCA and a
simulated quantum PCA (quantum phase estimation), reduces the sensors to a few
components, scores each cycle for degradation and reports NORMAL / EARLY
DEGRADATION / HIGH ANOMALY.

Requirements: MATLAB R2021a or newer. No toolboxes.

## Step-by-step

1. Unzip, open MATLAB, `cd` into `QEngine`.
2. Get the data: search "NASA C-MAPSS Turbofan Engine Degradation Simulation
   Data Set" (NASA Prognostics Data Repository), unzip, copy `train_FD001.txt`
   (and `train_FD003.txt` if you want it) into `QEngine/data/`.
3. `run('tests/test_qengine.m')` - should end with "All tests passed."
4. `run_qengine_demo` - prints the classical-vs-qPCA table and a 6-panel figure.
   Fix anything here before opening the app.
5. `launch_qengine` - the app opens. Demo order:
   - Tab 1: pick an engine (the last 20 % of engines are held out).
   - Tab 2: look at a sensor drifting over life.
   - RUN CLASSICAL PCA -> Tab 3: scree plot and loadings.
   - RUN qPCA -> Tab 4: circuit, phase histogram, eigenvalue table.
   - Tab 5: anomaly score and 3D health map; press "Animate trajectory".
   - COMPARE -> Tab 6: metric table and eigenvalue bars.
   - Tab 7: noise sweep and component sweep.
   - Move the noise slider or k spinner and watch everything update.

Without the NASA files the app falls back to "Synthetic demo" data. That data
is generated by `generateSyntheticCMAPSS.m`; it is not NASA data and is far
cleaner than the real thing. Never report numbers from it.

If you must hand in a `.mlapp` file: App Designer -> New -> blank app, then
recreate the layout and call the `core` functions from the callbacks. The
callbacks in `QEngineApp.m` can be copied across almost unchanged.

## Frozen methodology

**Data.** FD001 (one operating condition, one fault mode; FD003 also works).
FD002/FD004 have six operating regimes and would need per-regime
normalisation, so they are out of scope. Sensors with two or fewer distinct
values are dropped, which leaves 14 on FD001: 2, 3, 4, 7, 8, 9, 11, 12, 13,
14, 15, 17, 20, 21. The first 80 % of engines fit the model, the rest are held
out. Sensors are z-scored with the fitting engines' mean and std.

**Classical PCA.** C = XᵀX / N, `eig`, sorted descending.

**qPCA.** ρ = C / tr(C) is a valid density matrix. Padded from 14 to 16
dimensions it lives on 4 qubits. U = exp(2πiρ) has eigenphases equal to the
eigenvalues of ρ, so phase estimation with t ancilla qubits returns
m ≈ λ·2ᵗ with probability λ and leaves the system register in the matching
eigenvector (Lloyd, Mohseni, Rebentrost 2014). `quantumPCA.m` evolves the
exact state through Hadamards, controlled-U^(2^k) and the inverse QFT, then
reads eigenvalues from the phase peaks (centroid of the peak) and
eigenvectors from the post-measurement system state.

**Anomaly score.** Project to k components, z = Vₖᵀx. Healthy region = mean
m₀ and covariance S₀ of the first 20 % of each fitting engine's life.

    d²(x) = (z - m₀)ᵀ S₀⁻¹ (z - m₀)
    A(x)  = 1 - exp(-ln 2.5 · d² / d²₉₉)

d²₉₉ is the 99th percentile of healthy d², so A = 0.60 exactly at that
boundary. A is smoothed over the last 5 cycles. A < 0.60 NORMAL,
0.60-0.85 EARLY DEGRADATION, above 0.85 HIGH ANOMALY.

**Metrics.** Eigenvalue relative error, component fidelity |⟨v_c|v_q⟩|,
subspace overlap, reconstruction error on held-out engines, AUC separating
healthy cycles from the last 30 cycles before failure on held-out engines,
run time.

## What to say honestly in the report

- This is a classical simulation of the quantum algorithm. qPCA will be
  slower than `eig` here; that is expected.
- U is built with `expm`. The step that gives qPCA its theoretical speed-up
  (density-matrix exponentiation from copies of ρ, plus QRAM loading) is not
  simulated, and no speed-up is claimed.
- Reading eigenvectors out of the system register needs state tomography on
  real hardware. With "Exact" shots the app reads them directly, so fidelity
  is ~1 and the only qPCA error is the phase resolution (1/2ᵗ). With finite
  shots a simple 1/sqrt(n) noise model is added to the tomography; it is an
  approximation, not a hardware model.
- The healthy window and the "last 30 cycles" label use the known failure
  time, which is fine for evaluation on run-to-failure data but would not be
  available on a live engine.
- Thresholds 0.60 and 0.85 are design choices; state them as such.
